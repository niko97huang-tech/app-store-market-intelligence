# 推广前检查清单

这份清单的目标不是继续扩功能，而是帮助这个项目在对外推广前，把“价值表达、首次体验、案例证明、交付完整度”补到更合理的状态。

适用场景：

- 准备发 GitHub README 首轮推广
- 准备发 V2EX / 掘金 / X / Hacker News / 即刻 / 小红书
- 准备做项目介绍文章、演示视频或案例分享

## 这份清单怎么用

建议按优先级分三层：

- P0：不做会明显影响传播效果
- P1：会显著提升转化和理解效率
- P2：锦上添花，适合在第一波推广后继续补

## 推广前 10 项

### 1. 有一个能讲清楚价值的真实案例

目标：

- 不是只说“它能做什么”
- 而是说“它帮我发现了什么、排除了什么、节省了什么”

最低标准：

- 至少有 1 个真实分析案例
- 能展示赛道判断、风险提示和最终建议
- 最好能说明“因此少做了什么”或“因此决定做什么”

建议产物：

- `docs/case-study-01.md`
- README 中一段 3 到 6 行摘要
- 一张 Dashboard 截图

### 2. README 首屏 10 秒内能让人看懂

目标：

- 用户一进仓库就知道这不是普通榜单爬虫

最低标准：

- 有一句话定位
- 有“为什么值得看”
- 有 3 分钟快速体验
- 有一个明确主受众

建议避免：

- 上来先讲内部架构
- 首屏堆太多模块名称
- 一开始就进入长篇设计说明

### 3. 首次体验尽量短

目标：

- 用户在很短时间内看到报告、机会卡或 Dashboard

当前仓库已具备：

- 样例 run
- 样例 analysis
- 样例 dashboard
- 标准验证命令

推广前建议继续补：

- `npm run demo`
- 或一个更直接的 sample 命令别名

要求：

- 不依赖用户先抓新数据
- 不依赖额外外部服务
- 尽量 3 分钟内看到最终页面

### 4. 把主受众先收窄

目标：

- 第一波传播先服务一个最容易共鸣的人群

建议第一优先受众：

- 独立开发者
- AI 产品实验者
- 会自己做产品方向筛选的人

建议第一波核心表达：

- 别再拍脑袋选 App idea
- 先用数据和证据把伪机会排掉

### 5. 明确展示“决策系统”而不是“数据脚本”

目标：

- 强化项目真正的差异化

最低标准：

- README 或文档里明确展示：
  - Evidence Schema V3
  - Recommendation Ladder
  - 多角色评审
  - 最终动作建议分级

建议表达方式：

- 用图或表格解释：
  - 输入是什么
  - 中间如何判断
  - 输出如何区分“继续观察 / 深入研究 / 快速验证 / 暂不优先”

### 6. 准备可截图传播的结果页

目标：

- 让用户、读者或你自己在社交平台上容易展示结果

最低标准：

- 至少 1 张 Dashboard 截图
- 至少 1 张机会卡或决策卡截图
- 最好有 1 张“本周值得关注类目”或“伪机会 Top 5”截图

建议：

- 截图不要只截终端
- 尽量展示最终洞察页面

### 7. 给项目一个更明确的发布节奏

目标：

- 让外部读者知道项目不是一次性提交

最低标准：

- 一个明确版本号
- CHANGELOG 持续更新
- README 中有下一步方向

推广前建议：

- 发布一个 GitHub Release
- 把当前版本定义为 `v0.x` 或 `v1.0-preview`

### 8. 给推广准备 3 套不同文案

目标：

- 不同社区讲不同语言

建议至少准备：

- 面向独立开发者版
- 面向产品 / 研究版
- 面向 AI 工程 / Agent 工作流版

每套文案都要回答：

- 这个项目替代了什么低效动作
- 它怎么帮用户少走弯路
- 为什么现在值得试

### 9. 确保文档与实际能力一致

目标：

- 不制造虚假期待

推广前必须检查：

- README 里写的命令都能跑
- 文档里的输出路径真实存在
- 不能写“demo”但仓库里没有对应命令
- 不能写“AI 自动决策”但实际只是静态打分

建议：

- 每次改 README 后跑一次最小验证
- 优先用现有能力组织叙事，而不是先写未来能力

### 10. 准备一个推广后的收口动作

目标：

- 第一波流量进来后，有地方承接反馈

建议至少补齐：

- `Issues` 模板
- 反馈入口或讨论区
- README 中的贡献说明
- 一个“如果你想试这个项目，建议从哪里开始”的路径

## 推荐的推广前顺序

建议按下面顺序执行：

1. 先补 1 个真实案例
2. 再改 README 首屏
3. 再优化首次体验
4. 再准备截图和传播文案
5. 最后发首轮社区推广

## 最小验收方式

如果你准备在本仓库里正式推进“推广准备”，推荐至少做一次：

```bash
npm run check
npm run test:analysis
npm run verify:analysis -- --base-run-id run_2026-04-11_full --target-run-id run_2026-04-13_full --top-n 10
```

## 当前对这个仓库最重要的提醒

这个项目当前最缺的通常不是新的分析模块，而是：

- 一个让人记住的句子
- 一个让人信服的案例
- 一个让人愿意转发的结果图

只要这三样补上，现有工程底子已经足够支撑第一波推广。
