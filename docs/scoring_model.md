# 评分模型说明

## 设计原则

当前项目主要基于两次快照数据，因此评分模型强调：

- 优先用现有数据可解释地产生结果
- 对无法直接证明长期趋势的部分，明确标注为代理分
- 避免只给一个黑盒总分
- 让最终报告能解释“为什么是这个分数”

在 V2.1 中，评分模型已经接入轻量趋势层。也就是说，系统会在目标快照之前自动装载最近一段时间内的历史 run，把趋势代理信号并入持续性判断，但仍不会把它误写成长期趋势结论。

## 评分维度

### growth_score

衡量增长强度，主要参考：

- 新进榜数量
- 快速上升数量
- 平均正向排名改善幅度
- 高位区间上升数量
- 榜单变化广度

### persistence_score

持续性代理分，主要参考：

- 多个 app 同时改善，而不是单点异动
- 同分类多个榜单是否同时出现变化
- 代表 app 的版本更新时间是否能部分解释变化
- 代表样本是否足够分散
- 该方向在多次历史快照中是否持续出现
- 当前高位应用在历史窗口中的复现率
- 历史窗口内净上升 app 数量
- 历史窗口内连续改善 app 数量
- 高位换手率是否过高

注意：这不是长期趋势的真实分，而是当前数据条件下的代理判断。如果历史 run 少于 3 次，这一维会自动退化为偏保守的弱趋势判断。

### competition_score

竞争友好度，越高表示越容易切入。主要参考：

- 高位新进入者数量
- 头部类型集中度
- 名称与定位集中度
- 代表应用评分体量

同时内部保留：

- `competition_pressure_score`

用于表示反向竞争压力。

### monetization_score

变现清晰度代理分，主要参考：

- 免费榜 / 付费榜 / 畅销榜联动
- 当前榜单类型
- Top10 平均评分人数
- 同分类是否存在畅销榜表现

### execution_feasibility_score

执行可行性代理分，主要参考：

- 品类复杂度代理
- 头部集中度
- 样本覆盖情况

### differentiation_score

差异化空间分，主要参考：

- 应用名称 token 集中度
- 头部类型集中度
- 高位新进入者数量

### overall_score

综合分由多维评分加权得出，不是简单平均，也不等同于最终决策。

最终是否进入：

- `observe`
- `research`
- `validate`
- `deprioritize`

还会受到证据审计和反方审稿的约束。

## 最终建议不等于总分

V2 的最终建议由 `decision_chair` 决定，综合考虑：

- 需求是否成立
- 增长是否成立
- 商业化是否成立
- 证据是否足够
- 反方风险是否过强

因此：

- 高分不一定直接 `validate`
- 中等分也可能先 `research`
- 若证据不足，再高分也可能只能 `observe`
