# 新版本开发计划

## 1. 版本定位

当前项目已经完成了从榜单采集、快照对比到 V2 决策型报告的基本闭环，但要把它发展成一个真正能证明工程能力、产品判断能力和研究能力的代表性项目，还需要从“单次分析工具”继续演进为“可持续运行的 App Store 市场情报系统”。

新版本目标不再只是继续补几张报表，而是围绕以下三个升级方向推进：

- 从“两次快照判断”升级为“连续趋势判断”
- 从“Markdown/CSV 输出”升级为“可演示、可使用、可复核”的产品化体验
- 从“个人脚本仓库”升级为“稳定、可验证、可复用的开源项目”

建议将下一版本命名为：

- `V2.1`：趋势层 + 证据增强层
- `V3.0`：产品化展示层 + 自动化运行层 + 开源标准化

## 2. 新版本总目标

### 2.1 产品目标

让系统回答以下更有价值的问题：

- 哪些方向值得继续观察 7 天以上
- 哪些机会是持续增强而不是短期噪音
- 哪些赛道适合做研究、验证、放弃
- 哪些应用值得进入竞品矩阵
- 哪些结论可以进入 MVP 验证层

### 2.2 工程目标

让项目具备：

- 连续多天分析能力
- 可视化演示能力
- 自动运行能力
- 回归验证能力
- 开源可读性与可复用性

### 2.3 代表作目标

把项目打造成一个能体现以下能力的作品：

- 数据采集与清洗
- 结构化分析建模
- 决策型报告生成
- 产品化设计思维
- 可持续工程化交付

## 3. 版本范围

### 3.1 本轮必须完成

#### A. 趋势分析层

- 引入连续多 run 分析，而不仅是 base vs target
- 支持最近 7 天 / 14 天 / 30 天趋势计算
- 输出趋势稳定性、波动率、连续上升天数、持续上榜天数
- 在报告里加入趋势证据，不再只依赖两次快照

#### B. 赛道判断增强

- 增强 `persistence_score`
- 引入“持续增强机会”和“短期噪音机会”区分
- 引入“高优先观察名单”和“验证名单”
- 进一步减少无意义的泛化结论

#### C. 竞品研究辅助层

- 对 top opportunity 输出更适合人工研究的竞品摘要
- 自动生成建议关注的代表应用列表
- 支持后续接截图、描述、评论抓取

#### D. 导出与结果可读性增强

- 增加趋势相关 CSV/XLSX sheet
- 优化 Markdown 报告结构
- 减少“看起来很多，但无法决策”的输出

### 3.2 本轮应完成

#### E. 轻量展示层

- 新增本地 dashboard 或静态 HTML 报告页
- 至少支持：
  - 选择 analysis_id
  - 查看 executive summary
  - 查看机会卡
  - 查看 panel review
  - 查看负面结论

#### F. 运行稳定性增强

- 数据完整性校验
- 趋势分析的缺失 run 容错
- 输出 schema 稳定化
- 更清晰的运行日志

### 3.3 本轮可预留但不强制完成

#### G. 自动调度与通知

- cron / 定时日更
- 失败告警
- 自动生成日报

#### H. 更深层竞品内容抓取

- 截图抓取
- 描述抓取
- 评论抓取
- 更新说明抓取

## 4. 开发拆分

### 模块 1：多日趋势分析

#### 目标

把当前“两次快照 diff”升级成“连续时间序列分析”。

#### 需要新增

- `src/analysis/trend-loader.js`
- `src/analysis/trend-metrics.js`
- `src/analysis/trend-summary.js`

#### 主要能力

- 从 `data/runs/index.json` 按时间选取最近 N 个 run
- 聚合同一 `category_id + brand + app_id` 的多日轨迹
- 计算：
  - 连续上升天数
  - 连续出现天数
  - 平均排名变化
  - 波动率
  - 高位停留时间
  - 多榜单共振情况

#### 验收标准

- 能在没有新增外部依赖的前提下跑通
- 新版报告可引用趋势证据
- `persistence_score` 不再完全依赖两次快照代理

### 模块 2：趋势增强版评分模型

#### 目标

让评分更符合“继续跟踪 / 深入研究 / 快速验证”的真实判断逻辑。

#### 需要修改

- `src/analysis/scoring.js`
- `src/analysis/panel-review.js`
- `src/analysis/decision-chair.js`

#### 主要能力

- 加入趋势证据到：
  - `growth_score`
  - `persistence_score`
  - `competition_score`
- 加入趋势不足时的惩罚逻辑
- 让 `decision_chair` 能区分：
  - 单次异动
  - 持续增强
  - 有商业化但难执行
  - 有需求但竞争过强

#### 验收标准

- 高分机会不再大量停留在没有理由的 observe
- report 能明确区分“观察”和“验证”的分界

### 模块 3：证据增强层

#### 目标

让每个结论背后都有更像“研究 memo”的证据，而不只是榜单波动。

#### 需要新增

- `src/analysis/representative-apps.js`
- `src/analysis/evidence-enrichment.js`

#### 主要能力

- 为每个机会聚合：
  - 代表 app 的版本更新节奏
  - 评分变化特征
  - 价格结构
  - 类目内的榜单联动关系
  - 名称和定位集中度

#### 后续扩展位

- 截图
- 描述
- 评论
- release notes 深度提取

#### 验收标准

- 每个机会卡的证据部分明显更具体
- 负面结论也能给出明确证据

### 模块 4：竞品矩阵准备层

#### 目标

让报告直接服务于下一步人工研究，而不是止步在“值得看”。

#### 需要新增

- `src/analysis/research-brief.js`

#### 主要能力

- 对 top opportunity 输出：
  - 建议研究对象
  - 建议补抓字段
  - 推荐做的竞品矩阵维度
  - 建议验证的核心假设

#### 验收标准

- `next_step_actions` 更具体
- 从“看报告”能自然衔接到“做研究”

### 模块 5：展示层

#### 目标

让项目可以被演示、被理解，而不仅是被运行。

#### 建议方案

优先做轻量实现：

- `scripts/render-report-html.js`
- `data/analysis/<analysis_id>/report.html`

如果时间允许，再演进为：

- `web/` 轻量静态 dashboard

#### 首期页面最小范围

- Executive Summary
- Top Opportunities
- Negative Findings
- Panel Reviews
- Final Decisions

#### 验收标准

- 不需要复杂前后端即可打开查看
- 能作为开源项目首页演示素材

### 模块 6：自动化与运行稳定性

#### 目标

把项目从“可手动跑”升级成“可持续运行”。

#### 需要新增

- `src/analysis/data-validator.js`
- `scripts/daily-run.sh` 或等价脚本

#### 主要能力

- 检查 run 是否缺文件
- 检查 diff 是否缺字段
- 检查 export 是否完整
- 记录失败点

#### 验收标准

- 连续多天运行不会因为单次缺失直接崩掉
- 错误信息更可读

### 模块 7：测试与回归

#### 目标

让规则更新不会悄悄破坏报告质量。

#### 需要新增

- `tests/analysis/`
- 至少一组固定样本回归测试

#### 最小测试范围

- evidence pack 生成
- scoring 输出结构
- panel review 规则
- decision chair 仲裁逻辑
- export tables 字段稳定性

#### 验收标准

- 可以快速验证 V2/V2.1 修改是否破坏旧行为

## 6. 推荐开发顺序

建议按以下顺序推进，不要并行把战线拉太长：

1. 趋势层
2. 评分模型升级
3. 研究辅助层
4. 导出升级
5. 展示层
6. 自动化
7. 测试
8. 开源打磨

## 7. 开源项目打磨项

如果要把它做成能证明自己的代表作，除了功能本身，还要补以下内容：

- 更清晰的项目定位
- 一键运行示例
- 示例输出截图
- 架构图
- 方法论说明
- 真实案例分析
- 版本路线图

## 8. 当前版本结论

当前项目已经具备：

- 数据采集能力
- 快照 diff 能力
- V2 决策型报告能力
- 多角色规则化评审能力
- CSV/XLSX 输出能力

下一阶段最值得投入的开发，不是继续加更多“观察字段”，而是：

- 趋势层
- 研究辅助层
- 展示层

这是最能让项目从“做得不错”升级成“足够证明你”的路径。
